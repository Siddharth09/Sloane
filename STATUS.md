## What we're building

A voice-cloning platform, live in production, with video cloning intentionally paused as a sold feature (see below).

- **Preset voices:** type text, hear it narrated in one of **10 named, fine-tuned voices** — Vicky, Patrick, Alice, Megan, Katie, Brad, Izzy, Robbo, Michelle, Mark (customer-facing names; internal folder/git identifiers stay neutral, e.g. `art_instructor`, `voice_business` — see `web/src/components/VoicePicker.tsx` for the id→name mapping). Fully working, live.
- **Clone any voice:** upload ~10-20 seconds of anyone's voice, type any text, get it narrated back in that voice (zero-shot cloning). Working, live.
- **Video cloning:** **not sold as a feature right now** (home page still honest), but the product spec is now **locked** (2026-09-09) — four products total: (1) audio/preset voices, (2) audio/custom voice, (3) **talking-head video** — user uploads a photo or video + audio (typed text in a Lucy voice, or their own uploaded audio), Kling Avatar lip-syncs it, **voice is ours**, (4) **cinematic video** — user gives a text prompt (e.g. an exotic location) + a photo, Veo generates the scene with **its own voice/dialogue, not Lucy's** (dubbing doesn't lip-sync well against that much motion). Full spec, required honesty disclaimer copy (face distortion risk + third-party data sharing, both explicitly mandated), and a list of real gaps not yet addressed (photo-consent, content moderation, failed-generation credit policy, and more) are in [`PROJECT_CONTEXT.md`](./PROJECT_CONTEXT.md) Sec 13. **Not built yet** — `/api/generate-video` doesn't exist; video credit caps exist in code (see Billing below) but nothing spends them yet. Points users to Kling / Utopai's PAI as external options meanwhile.

It runs as:
- A **web app** (Next.js, live at **lucylabs.app**, deployed on Vercel)
- An **iOS app** (Expo/React Native, mirrors the web app's voice features) — **not yet submitted to the App Store, and not yet confirmed working on a real device.** Brought to feature/style parity with web, and a real background-rendering bug was found and fixed, but the actual "run it on a real iPhone via Expo Go" verification step (handed to the user, since this environment can't run the iOS Simulator) was never confirmed completed this session — **check this first** if picking up mobile work.
- A **GPU inference server** (FastAPI, `scripts/06_inference_server.py`) on a RunPod pod (`sloane-retrain`, proxy URL in `web/.env.local` as `INFERENCE_SERVER_URL`) that both apps call through Next.js API proxy routes (never called directly by clients)

### Audio generation quality — several real bugs found and fixed
- **Truncation bug**: Chatterbox's alignment-stream safety mechanism occasionally forces early EOS. Fixed with a duration-based retry (`generate_sentence_with_retry`).
- **Word-skipping bug**: added real content verification — transcribe each generation with faster-whisper, compare word overlap against the input text, retry on mismatch.
- **Unnatural flat sentence endings**: real DSP fix using the WORLD vocoder (`pyworld`, `apply_terminal_fall`) — forces F0 to actually slope downward from its peak. Went through two broken attempts before landing correctly (see PROJECT_CONTEXT.md Sec 11 for exactly why the first two didn't work) — applies to every voice automatically.
- **Multi-sentence text sounding rushed/disconnected/emotionless**: root-caused correctly — every sentence was being generated as a fully isolated model call with zero cross-sentence context, then stitched with an identical digital-silence gap. Not a training problem, a pipeline problem (affects every voice equally). Fixed by grouping consecutive sentences into one generation call (`chunk_sentences`, up to ~40 words, smaller for data-limited voices — see below) plus randomized pause-length jitter. A synthesized "breath" sound was also tried at pause points, then **removed** per direct feedback ("very unnatural") — pause jitter and chunking stayed, breath did not.
- **`plan_delivery()`** (new, built during this session via a parallel Mac-based Claude Code session working the same file, reviewed and deployed by this session): a real heuristic layer that reads punctuation/discourse cues in the text (questions, exclamations, ellipses/hesitation, quoted dialogue, list structure, soft vs. energetic language) and translates them into small bounded offsets to Chatterbox's real knobs (exaggeration/cfg_weight/temperature) plus a pause-length multiplier — not a fake emotion classifier. Merge order: default → per-voice baseline → these offsets → explicit client override. Live and tested in production.
- **Michelle (meditation) — root cause found and actually fixed at the data level, not just mitigated**: `scripts/03_chunk_by_speech.py` was silently **discarding** any transcribed segment longer than her clip-length cap instead of splitting it. Guided-meditation narration has long pauses, so whisper's VAD merges speech across them into segments that almost always exceeded the cap — meaning **only 6.6 of ~50 minutes** of her already-cleaned (vocal-isolated) source audio ever reached training data. Fixed to split at the largest internal word-to-word gap instead of discarding; recovered **318 clips / 29.7 minutes** from the *same* source audio. Re-ran the pipeline (03 → 05 → 09) on the pod; re-running 05 for all speakers as a side effect reset the speaker-isolation filtering for `voice_business`/`voice_finance`/`voice_broadcast` (05 regenerates unfiltered metadata for everyone) — caught this and re-ran 09 to correctly re-apply their cluster filters, verified row counts match pre-existing values exactly.
- **Michelle/Robbo — long-INDIVIDUAL-sentence bug found and fixed, 2026-09-09**: testing all 10 voices with a long multi-sentence paragraph as part of "make sure all voices are good for very long sentences too" surfaced a real, reproducible bug — Michelle's `MAX_CHUNK_WORDS_BY_VOICE` cap (14 words) was being silently bypassed. `chunk_sentences()` correctly grouped short sentences up to the cap, but when a single sentence on its own already exceeded the cap (very common in normal prose — e.g. a 24-word sentence), it emitted that whole sentence as one oversized chunk rather than discarding it, defeating the cap entirely. Her fragile fine-tune then failed almost every attempt on these oversized chunks, producing a 7.4s clip for text that should run ~20s. Fixed with a new `split_long_sentence()` step that splits an over-length sentence at clause boundaries (commas/semicolons) first, falling back to a hard word-count split only if a single clause alone still exceeds the cap. Verified live against the pod: same test text now generates in correctly-sized 11-14 word chunks and produces 19.9s (Michelle) / 23.6s (Robbo) of audio — both back in the normal range; re-checked `voice_business` (no per-voice cap) and `art_instructor` to confirm no regression. Committed and deployed (`scripts/06_inference_server.py`).
- **Retraining both on their expanded datasets — completed 2026-09-09**: `sloane-video` pod remained stuck ("not enough free GPUs") from the day before, so ran the queued Robbo data-processing job (`process_robbo.py` — vocal separation, chunking, metadata, re-applying the other voices' isolation filters) directly on `sloane-retrain` instead, since the whole pipeline lives on the shared network volume and that pod was already up. Completed cleanly: **694 clips / 52.3 minutes** for Robbo (deliberately not speaker-isolated, blending both men per the explicit ask), and the isolation-filter re-apply step again produced matching row counts for the other voices (374/514, 329/2368, 168/226) — no regression. `scripts/07_finetune_new_voices.sh` on the pod was stale (still targeted `voice_comedy`/`voice_meditation` from an earlier run) — redeployed the local copy (`VOICES=(voice_meditation voice_sales)`) before training. Both LoRAs trained and merged successfully (`chatterbox-ft-voice_meditation` and `chatterbox-ft-voice_sales`, in place at the same `adapter_dir` paths `PRESET_VOICES` already pointed to — no code path changes needed, just a server restart to drop the old cached weights). **Honest result**: re-tested with the same long-sentence text post-retrain — both produced healthy-length audio (24.5s Michelle, 26.2s Robbo) and per-chunk failed-attempt durations looked somewhat healthier than before (2-2.7s vs. 0.12-2s pre-retrain), but the server log still shows a high per-chunk retry-exhaustion rate for both voices ("all 4 attempts came back bad" firing repeatedly). **Retraining on more data measurably helped but did not eliminate the underlying fragility** — Chatterbox's alignment-stream forced-EOS behavior on these two voices looks like it needs meaningfully more data or a different LoRA config to fully resolve, not just one retrain. Worth a closer look (more data, different `lora_r`/`lora_alpha`, or more epochs) if voice quality for these two remains a priority.
- **Robbo (sales)**: root cause confirmed precisely earlier — only ~16 training clips (9MB) vs. 500+ clips (140-600MB) for other voices. A DSP mitigation (`apply_pitch_jitter`) shipped as a stopgap. The new 58-minute source video (two similar-sounding men, deliberately blended rather than isolated) is now fully processed and retrained (see above) — real improvement, not yet a full fix.
